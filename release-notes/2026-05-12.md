# Release Notes - 2026-05-12

## Feature Name
- Overview Date Filtering, QA Review Reliability, And Stable Local + LAN Access On Port 8767

## What’s New
- `/overview` now uses a single stable date-selection flow with quick ranges and Shopify-style calendar behavior, without page alignment shifts when changing the date mode.
- `/quality` and `/qa/frame-review` now use corrected backend-driven date filtering, better table linkage, and paginated review loading so teams can browse historical scan images more reliably and faster.
- IRIS local and same-LAN access on port `8767` was hardened: Windows firewall diagnostics and helper tooling were added, `localhost` startup now includes an IPv6 bridge for `::1`, and LAN access remains available through `http://192.168.1.113:8767/`.
- Operational handover was updated so future work preserves the supported startup flow and both local and LAN access behavior.

## Impact
- Managers can filter `/overview` by real business date ranges without UI reflow or confusion between shortcut and calendar modes.
- QA teams can review frame data across more dates with more consistent filtering and faster page loads on `/quality` and `/qa/frame-review`.
- Local users and devices on the same network can open IRIS more reliably through both `http://localhost:8767` and `http://<LAN-IP>:8767/`.
- Future agents and developers now have clearer startup and network guidance, reducing regressions during deployment or troubleshooting.

## Metrics / Monitoring
- KPI being tracked: successful date-filtered loads for `/overview`, `/quality`, and `/qa/frame-review`.
- Expected improvement: fewer QA review misses, lower page-load cost from server-side filtering/pagination, and fewer support issues caused by broken localhost or LAN routing.
- Dashboard / Tool used: browser verification on `localhost`, LAN URL checks, backend route validation, and current release documentation in `CHANGE_LEDGER.md` and `docs/AI_HANDOVER_STORAGE.md`.
- Monitoring owner: Development Team

## Risks / Known Issues
- Same-LAN access still depends on the Windows host firewall and network profile; the helper script reduces setup friction, but device-specific router isolation can still block access.
- The localhost IPv6 bridge is part of the supported Windows startup path, so future launcher changes must preserve it or replace it with an equivalent `::1`-safe solution.
- Historical QA browsing depends on the underlying scan data already existing in SQLite with the expected date linkage.

## Rollback Plan
- Revert the relevant commits if needed:
  - `git revert 8c71ef22 1df22308 1c0de1ce c7ab33c2 a4dc5abb 5be081fd`
- Rebuild the frontend and refresh `backend/app/static` if rolling back UI-related changes.
- Restart IRIS through the supported `start_iris.bat` / `start_iris.ps1` path after rollback.
